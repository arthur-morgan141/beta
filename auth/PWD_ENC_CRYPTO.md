# Deep Dive Cryptographic Specification: `#PWD_ENC:2` Binary Envelope

## 1. Overview & Mathematical Definition

Meta Muse v15 (`com.facebook.aura` v15.0.0.3.156) uses a proprietary hybrid envelope encryption scheme identified by the prefix `#PWD_ENC:2`. The plaintext password is never transmitted in the clear, nor is it encrypted with raw RSA. Instead, a multi-layer hybrid cryptographic construction combining **AES-256-GCM** (authenticated symmetric encryption) and **RSAES-PKCS1-v1_5** (asymmetric key encapsulation) is used, bound to the client's Unix epoch timestamp via Galois AEAD Additional Authenticated Data (AAD):

```
#PWD_ENC:2:<timestamp_epoch>:<base64_encoded_binary_envelope>
```

$$\text{Envelope} = \text{key\_id\_len} \,\|\, \text{key\_id} \,\|\, \text{rsa\_len} \,\|\, c_{\text{RSA}} \,\|\, \text{IV} \,\|\, \text{Tag} \,\|\, c_{\text{AES}}$$

Where:
- $K_{\text{AES}} \stackrel{\$}{\leftarrow} \{0,1\}^{256}$ (256-bit ephemeral cryptographic random symmetric key generated per session)
- $\text{IV} \stackrel{\$}{\leftarrow} \{0,1\}^{96}$ (96-bit ephemeral cryptographic random nonce / IV)
- $c_{\text{RSA}} = \text{RSAES-PKCS1-v1\_5}(PK_{\text{Meta}}, K_{\text{AES}})$ ($M = 256\text{ bytes}$ for RSA-2048)
- $(c_{\text{AES}}, \text{Tag}) = \text{AES-256-GCM}_{\text{Enc}}(K_{\text{AES}}, \text{IV}, \text{Password}, \text{AAD})$
- $\text{AAD} = \text{UTF-8}(\text{str}(\text{timestamp}_{\text{epoch}}))$ (e.g. `"1731146200"`)
- $\text{Tag} \in \{0,1\}^{128}$ (16-byte GHASH Galois Field Authentication Tag)

### Verified 7-Element Field Table

| Field Index | Element Name | Wire Offset | Field Length | Data Type | Implementation & Semantic Verification |
| :---: | :--- | :--- | :--- | :--- | :--- |
| **1** | `key_id_len` | `0x00` | 1 Byte | `uint8` | Length of public key identifier ($N$). Typically `0x01` or `0x02` (e.g. `1` for default key ID 41). |
| **2** | `key_id` | `0x01` | $N$ Bytes | `ASCII` | Public key ID string or encoded identifier matching Meta directory `key_id`. |
| **3** | `rsa_len` | $1+N$ | 2 Bytes | `uint16_be` | Big-endian length of the RSA ciphertext block ($M$). Evaluates to `0x0100` (256 bytes) for RSA-2048. |
| **4** | $c_{\text{RSA}}$ | $3+N$ | $M$ Bytes | Binary | RSAES-PKCS1-v1_5 encrypted ephemeral 32-byte AES-256 key (`EVP_SealInit`). |
| **5** | $\text{IV}$ | $3+N+M$ | 12 Bytes | Binary | 96-bit AES-GCM Initialization Vector / Nonce generated by OpenSSL engine. |
| **6** | $\text{Tag}$ | $15+N+M$ | 16 Bytes | Binary | 128-bit GHASH authentication tag retrieved via `EVP_CIPHER_CTX_ctrl(EVP_CTRL_GCM_GET_TAG, 16)`. |
| **7** | $c_{\text{AES}}$ | $31+N+M$ | $L$ Bytes | Binary | AES-256-GCM encrypted UTF-8 password bytes ($L = \text{len}(\text{Password})$). |

Total Envelope Byte Length:
$$\text{Length}_{\text{Total}} = 1 + N + 2 + M + 12 + 16 + L = 31 + N + M + L$$

## 4. Additional Authenticated Data (AAD) & Cryptographic Binding

A fundamental security invariant in `#PWD_ENC:2` is the cryptographic binding of the Unix epoch timestamp into the Galois Field authentication calculation:

$$\text{Tag} = \text{GHASH}_{H}(\text{AAD} \,\|\, 0^{u} \,\|\, c_{\text{AES}} \,\|\, 0^{v} \,\|\, \text{len}_{64}(\text{AAD}) \,\|\, \text{len}_{64}(c_{\text{AES}}))$$

### Security Properties
1. **Timestamp Tamper-Proofing:** Because the plaintext timestamp string is authenticated as AAD, altering the timestamp field in `#PWD_ENC:2:<timestamp>:<base64>` invalidates the GHASH tag during backend decryption, causing instant rejection.
2. **Replay Window Enforcement:** The Meta authentication backend enforces:
   $$|t_{\text{server}} - t_{\text{client}}| \le 300\text{ seconds (5 minutes)}$$
3. **Semantic Freshness:** Because an ephemeral 256-bit AES key and fresh 96-bit IV are generated per encryption call, encrypting identical passwords at different times yields completely different ciphertexts and tags.

## 6. Architectural Evolution: `#PWD_ENC:1` vs `#PWD_ENC:2`

| Security Attribute | Legacy Web `#PWD_ENC:1` | Modern Native v15 `#PWD_ENC:2` |
| :--- | :--- | :--- |
| **Symmetric Cipher** | AES-128-CBC | **AES-256-GCM (NIST SP 800-38D)** |
| **Integrity Mechanism** | Separate HMAC-SHA256 tag | **Built-in Galois Field (GHASH) AEAD** |
| **Replay Protection** | Session/Cookie bounded | **Cryptographic AAD Timestamp Binding** |
| **Vulnerability Resistance**| Padding oracle risk if MAC verification is not timing-safe | **Immune to padding attacks (Stream mode GCM)** |
| **Wire Overhead** | Hex-encoded strings | **Zero-overhead raw binary envelope, Base64 NO_WRAP** |
